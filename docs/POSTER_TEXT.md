# FORGEAI
## From a plain-English idea to a running app.

**Describe it. ForgeAI builds it, runs it, and checks that it works.**

### THE PROBLEM

An app idea is easy to explain and hard to turn into a working first version. Copying code from a chat does not automatically create a runnable project, start it, check its data flow, or show what failed.

### THE SOLUTION

ForgeAI turns a natural-language app description into a Flask + SQLite project, launches a local preview, and tests its API and sample database write. When provider access is unavailable, a clearly labeled replay keeps the exhibition demo available.

### HOW IT WORKS

1. **Describe** — Write what the app should do in plain English.
2. **Design** — ForgeAI creates a spec and a shared API/data contract.
3. **Build & run** — It generates the project files and starts the Flask app locally.
4. **Verify & repair** — It checks routes and sample persistence, then attempts a bounded repair if needed.

### WHAT YOU CAN SEE

- Live build log and pipeline
- Generated source code and app data blueprint
- Running app preview
- Route and SQLite verification results
- Focused modifications, version undo, and ZIP download
- Offline replay, labeled honestly

### TECH STACK

Python · Flask · SQLite · Gemini / Groq · Vanilla HTML, CSS & JavaScript

### RESULTS

One generated app project contains seven core files. ForgeAI reports the measured time and verification results for each build. Automated tests cover the generation contract, syntax gate, verifier, download route, and exhibition support.

**The “~2 days” comparison is an illustrative estimate, not a measured study.** A passing check is useful evidence, not proof that an app is secure or production-ready.
